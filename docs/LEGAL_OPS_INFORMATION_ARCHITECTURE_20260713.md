# Legal Ops 精简信息架构与真实指标口径

## 顶层导航

面向庞浩、刘聪：

1. **工作总览**：只展示当前用户有权数据的真实指标和待办。
2. **报告中心**：日报、周报、月报统一入口。
3. **案件工作台**：全部/原告/被告、阶段筛选、分页、单案详情。
4. **出差协同**：真实出差、候选、通知和回复状态。
5. **团队**：当前灰测团队和两名成员的案件/报告完成情况。

仅管理员：

6. **审计证据**：receipt、audit、来源和失败记录，分页脱敏展示。

主体知识库不再占用顶层主导航；作为“案件工作台”的辅助视图和单案“当事人关系”页签。管理员仍可从案件页进入主体搜索。

## 首页保留指标

| 指标 | 真实计算口径 | 可下钻 |
|---|---|---|
| 权限内案件 | principal `allowed_case_ids` 与非隐藏 Agent2Case 交集 | 案件列表 |
| 原告案件 | `case_type=plaintiff_case` | 原告筛选 |
| 被告案件 | `case_type=defendant_case` | 被告筛选 |
| 阶段分布 | 按案件类型映射 `Agent2Case.status` | 阶段筛选 |
| 有有效进展案件 | 至少一条 `deleted_at IS NULL` 的 CaseProgress | 案件列表 |
| 暂无有效进展案件 | 权限内案件减去有有效进展案件 | 案件列表 |
| 待回复追问 | active/awaiting_input Pending | 追问筛选 |
| 今日日报 | 当前本地业务日期、权限内用户的 DailyReport 状态 | 报告中心 |
| 待处理出差协同 | candidate/notified/accepted_by_one 状态 | 出差页 |
| 失败或阻断 | 当前 scope 的失败 receipt/outbox | 管理员审计页 |

暂不展示：风险案件、即将开庭、长期无进展。当前数据库没有可靠风险等级、开庭日期和 meaningful-progress 基准，显示会制造假口径。

## 案件阶段模型

### 原告案件

`拟诉 → 诉讼中 → 执行中 → 已结案`

映射：

- `intended_filing` → 拟诉
- `litigation` → 诉讼中
- `enforcement` → 执行中
- `closed` → 已结案

### 被告案件

`受理 → 开庭 → 审结 → 履行 → 已结案`

映射：

- `accepted` → 受理
- `hearing` → 开庭
- `adjudicated` → 审结
- `performance` → 履行
- `closed` → 已结案

## 案件卡片

必须由后端 DTO 返回：

- 我方角色：原告案件/被告案件；
- 案件名称、案件编号/案号；
- 当前阶段；
- 当前节点（无记录显示“暂未记录”）；
- 负责人中文名；
- 最新有效进展（软删除记录不进入）；
- 下一步计划；
- 开庭时间（无结构化数据时显示“暂未记录”）；
- 风险等级（无结构化数据时显示“暂未评估”）；
- 追问策略；
- 最近更新时间；
- 中文数据来源。

## 单案详情

页签：

1. 概览；
2. 生命周期；
3. 进展与计划；
4. 当事人关系；
5. 主动追问；
6. 日报投影；
7. 审计（管理员）。

生命周期以单案为根：

`案件开始 → 一级阶段 → 当前节点 → 实际进展事件 → 下一步计划`

只按当前导入阶段标记已到达/当前/未来，不把未来阶段伪造为已发生；所有事件节点必须来自真实 CaseProgress、LifecycleState 或 committed receipt。

## 页面状态

每个页面统一使用：加载中、空状态、无权限、网络失败/重试、保存中、保存成功、版本冲突、对象已删除、登录过期。写入成功后必须重新读取服务器状态。

## 实施结果

- live 两用户导航已经按上述五个业务入口收敛；Fixture 演示信息架构只保留在本地显式演示模式。
- 案件默认页已从多主体森林改为案件卡片、筛选和分页；原告/被告使用文字标签与不同阶段词典。
- 单案详情采用案件为根的生命周期；顶部六个区块导航均为真实按钮，点击定位真实区块，不再保留视觉假页签。
- 无结构化法院、案由、开庭日期、风险等级时不推导、不补造，统一展示“暂未记录/暂未评估”。
