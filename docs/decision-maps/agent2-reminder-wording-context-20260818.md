# Agent2 主动提醒、自然话术与承接填写

目标：让小律像服务同事的人，而不是要求同事适应系统流程。主动提醒既要自然、不重复，也要在确认送达后成为可安全承接的连续对话。

## #1：填写方便与安全确认如何取舍？

Blocked by: 无
Type: Grilling

### Question

用户用“是”“第一个做了”等简短回复承接提醒时，系统应优先省步骤还是再次确认？

### Answer

采用填写便利原则。已送达提醒和可信原条目足以唯一确定时，直接写入可恢复的今日日报草稿并展示结果，不自动提交；部分完成只写明确完成项，含糊回复再追问。提交、删除等高风险动作仍需明确授权。

## #2：提醒话术由模板还是 AI 生成？

Blocked by: #1
Type: Grilling

### Question

怎样减少固定话术疲劳，又不让 AI 改变事实？

### Answer

采用受约束的 Flash 生成。程序提供称呼、日期、实际缺项、提交规则、昨日计划原条目和近期已发话术；AI 只组织自然表达。生成结果必须通过事实核对，失败时使用简短备用话术。

## #3：主动提醒怎样进入连续对话？

Blocked by: #1, #2
Type: Grilling

### Question

怎样让用户回复“是”时，Agent2知道他承接的是哪条提醒和哪些原计划？

### Answer

仅把最终确认送达、本人绑定正确的提醒作为助手消息进入本人上下文，同时保存其引用的报告日期、稳定原条目和来源。用户回复由Agent2结合提醒语义理解；服务器只允许写入这些可信原条目。未确认送达、跨人或过期提醒不进入上下文。

当前缺口：线上只利用提醒事件保持目标日报日期，普通日报提醒正文尚未进入Agent2最近消息；只有晨报和专门验证过的主动消息具备该能力。

## #4：同一天多次提醒怎样避免疲劳？

Blocked by: #2
Type: Grilling

### Question

20点、22点等多次提醒应如何变化？

### Answer

同一天逐次缩短：第一次可说明如何填写；已填一部分时只说实际缺项；最后一次才说明自动提交规则。同一天首次称呼后不重复称呼和教程，并把近期已发送话术交给AI避免复述。
