# 绩效填写 Agent2 迁移延期记录

## 决定

- 保留当前线上已有的绩效填写功能及其现有入口和行为。
- 本轮不把绩效填写迁移到 Agent2，也不新增、替换或部署相关工具。
- “被告案件绩效查询”是独立能力，本决定不暂停该查询能力，也不撤回与查询答案事实校验有关的安全改进。
- 预计数月后由产品负责人重新决定是否启动迁移；在此之前，不借其他需求顺带改造绩效填写。

## 本轮发现但暂不处理的风险

- 当前绩效填写仍有独立于 Agent2 的旧处理链，语义理解、连续对话和个人记忆体验可能与 Agent2 不一致。
- 同一用户存在多个进行中任务时，旧链路的任务选择、字段归属和提交意图仍需专门验证。
- 迁移草案曾尝试把全部进行中任务装入 Agent2 上下文；若个别历史任务数据异常，可能影响整个对话，因此不能未经生产数据审计直接启用。
- 绩效填写写入需要版本冲突保护、原话留痕、修改前后审计和整批失败回滚；这些要求不能用临时兼容逻辑替代。

## 未来恢复迁移的最低门槛

1. 产品负责人明确重新启动，并确认范围、填写流程、提交口径和多任务交互。
2. 只读审计线上进行中任务，确认历史数据结构、人员归属和异常记录不会阻断普通对话。
3. 绩效填写必须接入 Agent2 的统一理解、上下文和工具流程，不得形成 Agent1 式关键词旁路或模型失败回退。
4. 写入必须校验本人、精确任务、精确版本和当前消息依据，并保留原话、修改前后内容与原因。
5. 使用隔离数据完成查看、填写、补充、修改、清空、提交、多任务歧义、重复消息和并发冲突测试；同时回归日报、记忆、查询和连续对话。
6. 发布前做真实数据只读验收，发布后只对明确授权的测试账号验证；不得给真实用户发送测试消息。
